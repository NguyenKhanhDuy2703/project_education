## Scope and requirement decisions

- **Business scope**: finish only work that is genuinely incomplete; do not reimplement items whose code and tests already exist.
- **Security boundary**: no learner SQL may reach platform PostgreSQL; no destructive database sync, `deleteMany`, or production/staging write is allowed without a verified target and explicit write gate.
- **Data lifecycle**: V3 curriculum is authoritative. Legacy V2 fixture work is migrated only when still required by an existing record; otherwise it is documented as superseded.
- **Edge cases**: benchmark failures, unavailable browser memory APIs, cold-cache variability, offline asset loading, dirty-tree overlap, and missing deployment credentials must produce an honest blocked/partial result rather than a fabricated pass.
- **Performance**: measurements must be generated by an executable browser harness and record environment/date; hard-coded benchmark numbers are not acceptable evidence.
- **UI/UX**: preserve the existing StudyIT design system. Footer completion requires keyboard access, visible focus, minimum 44px touch targets, readable mobile text, no horizontal overflow, correct routes, dynamic year, and no footer in the full-screen lab layout.

## Out of scope

- Re-running obsolete Git branch separation plans verbatim.
- Sending inter-agent completion messages that no longer have a live recipient.
- Redesigning the entire learner shell, legal pages, or SQL workspace.
- Automatic writes to a shared/staging/production database.
- Committing, pushing, or opening a PR without a later explicit user instruction.
